SECRETS / RELEASE GATES (mandatory)
-----------------------------------
  - Never commit or force-add secrets/ (gitignored). Do not `git add -f secrets/`.
  - Public packages must never include node_elgamal.priv or a shared
    client_ed25519.priv. Release scripts run _assert_no_priv / strip inject.
  - VPS/CDN/hosting providers may log IP-level metadata under their policies
    even when product no-log is enabled (see PRIVACY_POLICY.md §4).


1. PORTS
--------
  UDP 44044  — RPT tunnel (node listen)
  TCP 8080   — Node local status UI (title + current client count)

  Client apps connect to the configured RPT endpoint (default product host
  uses these ports on the operator's server).

3. DEPLOY NODE (operators)
--------------------------
  Custom RPT node (not WireGuard/OpenVPN). Tree: node/

  From a machine with SSH (password via environment — never commit):

    export RPT_SSH_HOST=YOUR_SERVER_IP
    export RPT_SSH_USER=root
    export RPT_SSH_PASSWORD='...'
    pip install paramiko cryptography
    python scripts/deploy_rpt_node.py

  Note: scripts/deploy_rpt_node.py authenticates with RPT_SSH_PASSWORD only
  (look_for_keys=False). For interactive admin SSH to a new VPS, use a normal
  OpenSSH key in authorized_keys; that path is separate from the deploy script.

  Or on the server after copying node/ to /opt/restore-privacy/node:

    bash /opt/restore-privacy/node/install.sh

  Tunnel DNS (privacy prep — clients default DNS to 10.88.0.1):
    # After rpt0 is up (install.sh also attempts this):
    bash /opt/restore-privacy/node/install_dns.sh
    # Config sample: node/unbound-rpt.conf (listen 10.88.0.1, ACL 10.88.0.0/24 only)
    # Do NOT open UDP/TCP 53 on the public WAN (not an open resolver).
    # Live FlokiNET/VPS apply: when the box is running, re-run install_dns.sh if needed.

  Node properties (operator reference):
    Admission  — authorized RPT client keys only (ElGamal + Pedersen + Ed25519)
    Crypto     — custom RPT2 data plane (ChaCha20-Poly1305 after handshake)
    Relay      — TUN + IP forward + MASQUERADE
    Privacy    — no user-info / session activity log files by design
                 (see PRIVACY_POLICY.md)


4. CLIENT APPS (developer / from-source)
----------------------------------------
  Windows client (source):
    pip install -r requirements.txt
    python -m client.windows
    # Run as Administrator for full system VPN (Wintun residual IP)

  Linux client (source — Ubuntu 20.04+ / Mint and similar):
    pip install -r requirements.txt
    # product residual path needs root + host TUN/`ip` (crypto alone is not enough)
    sudo python -m client.linux
    # residual public IP only when full tunnel succeeds (require_system_capture);
    # non-root runs fail honestly rather than claiming Connected.

  End-user Linux install package (baked manylinux cryptography wheels):
    python scripts/package_linux.py
    # produces restore-privacy-client-*-linux-x64.tar.gz under releases/
    # see README for install.sh / bin/privacy-restored; re-run package_linux on
    # every tag so CPython 3.8–3.12 wheels stay current.

  Android / Flutter:
    cd client_app
    flutter pub get
    flutter run
    # or: flutter build apk --release

  iOS / macOS (build on a Mac):
    client_app/ios/BUILD_ON_MAC.md
    client_app/macos/BUILD_ON_MAC.md
    # Residual IP requires signed Packet Tunnel / Network Extension; prep zips
    # alone are Mac-side work (see README Apple section).

  Layout:
    client/       — shared connect path + Windows / Linux native UIs
    client_app/   — Flutter multi-platform scaffolds
    node/         — server node
    status_page/  — public status + downloads
    scripts/      — deploy / release helpers


5. RELEASE PACKAGING (operators cutting a tag)
---------------------------------------------
  Process notes: scripts/RELEASE.md

  Use the **current tag** recipe only (today: scripts/build_release_0.1.8.py
  for v0.1.8). Historical scripts/build_release_0.*.py files are archives —
  for a new version, copy the latest script and bump VERSION / PRIOR_TAG /
  status_page/downloads.py catalog.

  Every release must keep:
    - _assert_no_priv (or equivalent) on release output
    - inject/provision of node_elgamal.pub only — never node_elgamal.priv
    - never force-add secrets/ to git
    - re-run python scripts/package_linux.py (also wired in build_release_0.1.8.py)

  Short cut example:

    python scripts/build_release_0.1.8.py
    # then gh release create <tag> with assets under releases/

7. SECRETS (operators — never commit private keys)
--------------------------------------------------
  Public installers do NOT ship private admission keys.

  Operator paths (gitignored examples):
    ./secrets/client_ed25519.priv
    ./secrets/node_elgamal.pub
    /opt/restore-privacy/secrets/   (on the node host)

  Without valid authorized client material, the cryptographic handshake
  will not admit the client. Treat private keys as credentials.

  Never put root passwords or *.priv files in git or public release zips.
  SSH login keys for the VPS live under the operator machine ~/.ssh/ — they
  are not RPT secrets/ and must not be mixed into release packages.
